# Эмулятор командной оболочки

Практическая работа по дисциплине «Конфигурационное управление».

**Вариант №19.**

## Общее описание

Проект представляет собой эмулятор UNIX-подобной командной оболочки
с графическим интерфейсом (Tkinter). Поддерживает параметры командной
строки, выполнение стартовых скриптов, виртуальную файловую систему
(VFS) из ZIP-архива и основные команды командной оболочки.

Выполненные этапы:

- Этап 1. REPL.
- Этап 2. Конфигурация.
- Этап 3. Виртуальная файловая система (VFS).
- Этап 4. Основные команды.

## Этап 1. REPL

На первом этапе реализован минимальный прототип эмулятора
с графическим интерфейсом.

Добавлены:

- GUI-окно на Tkinter;
- заголовок окна формируется из реальных данных ОС:
  `Эмулятор - [username@hostname]`;
- разбор команды и аргументов по пробелам;
- команды-заглушки `ls` и `cd`;
- команда `exit`;
- обработка неизвестных команд;
- обработка ошибок при выполнении команд.

Эмулятор работает в цикле до выполнения команды `exit`.

## Этап 2. Конфигурация

Добавлена возможность настройки эмулятора через параметры
командной строки.

Поддерживаются параметры:

- `--vfs` — путь к физическому расположению VFS (ZIP-архив);
- `--script` — путь к стартовому скрипту.

При запуске программа выводит отладочную информацию о переданных
параметрах.

Проверяется только существование файла стартового скрипта.

Если указан стартовый скрипт, команды из него выполняются
последовательно:

- команда отображается на экране перед выполнением;
- отображается результат выполнения команды;
- пустые строки пропускаются;
- строки, начинающиеся с `#`, считаются комментариями;
- при ошибке команды выводится сообщение, и выполнение скрипта
  продолжается со следующей строки;
- команда `exit` завершает работу эмулятора.

Если указан `--script`, эмулятор работает в headless-режиме
(без графического окна) — это позволяет запускать его
из shell-скриптов.

## Этап 3. Виртуальная файловая система (VFS)

Источник VFS — **ZIP-архив**. Содержимое загружается в оперативную
память при запуске эмулятора. Исходный архив при этом не
распаковывается на диск и не модифицируется.

Файловая система представляется вложенными словарями Python.
Для каждого объекта сохраняется тип (`dir` / `file`), владелец
и содержимое (для файлов — в виде байтов, что позволяет
поддерживать как текстовые, так и двоичные данные).

### Служебная команда vfs-info

Команда `vfs-info` выводит информацию о загруженной VFS:

- имя архива;
- хеш SHA-256 содержимого архива.

Пример:

```text
$ vfs-info
Имя VFS: minimal.zip
SHA-256: 545412b56a3013640cc33dbeafd673162eb15a271d6426a88d3238c139296fb0
```

Хеш вычисляется по байтам ZIP-файла и позволяет однозначно
идентифицировать конкретную версию VFS.

### Обработка ошибок загрузки VFS

Предусмотрена обработка следующих ошибок:

- файл VFS не найден;
- указанный файл не является ZIP-архивом.

При возникновении ошибки программа выводит соответствующее
сообщение и завершается с ненулевым кодом.

### Тестовые VFS

Для проверки загрузки подготовлены три ZIP-архива в папке
`tests/vfs/`:

- `minimal.zip` — минимальная VFS (один текстовый файл);
- `multiple.zip` — несколько файлов и вложенный каталог `docs`;
- `nested.zip` — три уровня вложенности каталогов
  (`level1/level2/level3/deep.txt`).

Архивы собираются из исходных директорий скриптом
`tests/build_vfs.py`:

```bash
python3 tests/build_vfs.py
```

## Этап 4. Основные команды

На четвёртом этапе реализована полноценная работа основных команд
с виртуальной файловой системой.

Поддерживаются команды:

- `ls`;
- `cd`;
- `date`;
- `wc`;
- `uptime`;
- `exit`.

### Обработка путей

Для работы с путями используется отдельный модуль
`src/path_utils.py`.

Поддерживаются:

- абсолютные пути;
- относительные пути;
- `.` — текущий каталог;
- `..` — родительский каталог;
- несколько последовательных `..`;
- повторяющиеся разделители;
- прямые и обратные слеши;
- сложные комбинации элементов пути.

Пример:

```text
/projects/student/files/../../archive/././docs
```

нормализуется до:

```text
/projects/archive/docs
```

Выход выше корня VFS невозможен.

### Команда cd

Команда `cd` изменяет текущий каталог внутри виртуальной
файловой системы.

Примеры:

```text
cd docs
cd /docs
cd ..
cd /
cd ./docs/../docs
```

При попытке перейти в отсутствующий каталог или в файл
выводится сообщение об ошибке, текущий каталог не меняется.

### Команда ls

Команда `ls` выводит содержимое каталога VFS.

Обычный запуск:

```text
ls
```

Поддерживаются ключи:

- `-l` — подробный формат вывода (тип, владелец, размер, имя);
- `-h` — удобное отображение размера (`B`, `K`, `M`, `G`);
- `-a` — отображение скрытых объектов и специальных элементов
  `.` и `..`.

Поддерживаются как объединённые, так и раздельные комбинации
ключей:

```text
ls -l
ls -h
ls -a
ls -la
ls -lh
ls -ah
ls -lah
ls -l -a -h
```

Ключи можно использовать вместе с путями:

```text
ls docs
ls ./docs
ls /docs
ls -l /docs
ls -lah /docs
ls /docs/.././docs
```

Без ключа `-a` объекты, имя которых начинается с точки,
не отображаются.

Неизвестные ключи и неверное количество путей обрабатываются
как ошибки.

### Команда date

Команда `date` выводит текущие дату и время операционной системы.

Пример:

```text
$ date
2026-10-16 00:00:33 MSK
```

Конкретный формат названия часового пояса зависит от настроек
операционной системы. Команда не принимает аргументы.

### Команда wc

Команда `wc` подсчитывает количество строк, слов и байтов
в файле VFS.

Формат вывода:

```text
СТРОКИ СЛОВА БАЙТЫ ИМЯ_ФАЙЛА
```

Пример:

```text
$ wc readme.txt
1 7 35 readme.txt
```

Команда принимает ровно один аргумент — путь к файлу.
Каталоги не поддерживаются, для них выводится ошибка.

### Команда uptime

Команда `uptime` показывает время работы эмулятора с момента
запуска в формате `Ч:ММ:СС`.

Пример:

```text
$ uptime
Uptime: 0:00:00
```

Команда не принимает аргументы.

### Состояние эмулятора

Текущая VFS и текущий каталог сохраняются в состоянии программы:

```python
state = {
    "vfs": vfs,
    "cwd": [],
    "vfs_name": "...",
    "vfs_hash": "...",
    "start_time": ...
}
```

Благодаря этому команды `cd`, `ls`, `wc` работают с текущим
состоянием файловой системы, а `uptime` — с моментом запуска.

### Стартовые скрипты этапа 4

Для проверки реализованных команд созданы два сценария.

`tests/stage4_success.txt` проверяет:

- `date`;
- `uptime`;
- обычный `ls`;
- ключи `-l`, `-h`, `-a`;
- комбинации ключей;
- абсолютные, относительные и сложные пути;
- переходы с помощью `cd`;
- `wc` с разными вариантами путей;
- команду `exit`.

`tests/stage4_errors.txt` проверяет обработку ошибок:

- `date` с лишним аргументом;
- `ls` с неизвестным ключом;
- `ls` с двумя путями;
- `cd` в несуществующий каталог;
- `wc` для несуществующего файла;
- `wc` для каталога.

Для общего запуска используется:

```bash
./tests/test_stage4.sh
```

При успешном выполнении выводится:

```text
STAGE 4 TESTS PASSED
```

## Структура проекта

- `src/` — исходный код эмулятора;
- `src/main.py` — основной файл (GUI + headless, параметры
  командной строки, загрузка VFS);
- `src/parser.py` — разбор пользовательского ввода;
- `src/commands.py` — команды и класс `CommandResult`;
- `src/path_utils.py` — обработка и нормализация путей;
- `src/vfs.py` — загрузка VFS из ZIP-архива, вычисление SHA-256;
- `tests/` — тесты, стартовые скрипты и тестовые VFS;
- `tests/build_vfs.py` — сборка ZIP-архивов VFS;
- `tests/vfs/` — исходные директории тестовых VFS;
- `tests/*.txt` — стартовые сценарии;
- `tests/*.sh` — shell-скрипты тестирования;
- `tests/test_*.py` — модульные тесты;
- `run.sh` — скрипт запуска;
- `README.md` — документация проекта;
- `.gitignore` — список файлов, исключённых из Git.

## Запуск

Обычный запуск (открывается графический интерфейс):

```bash
./run.sh
```

Или напрямую:

```bash
python3 -m src.main
```

## Параметры командной строки

Передача пути к VFS:

```bash
./run.sh --vfs tests/vfs/multiple.zip
```

Передача стартового скрипта:

```bash
./run.sh --script tests/start_ok.txt
```

Одновременная передача двух параметров:

```bash
./run.sh --vfs tests/vfs/multiple.zip --script tests/stage4_success.txt
```

## Тестирование

Сборка тестовых ZIP-архивов VFS:

```bash
python3 tests/build_vfs.py
```

Модульные тесты Python:

```bash
python3 -m unittest discover -s tests -v
```

Тестовые файлы:

- `tests/test_vfs.py` — загрузка VFS и SHA-256;
- `tests/test_paths.py` — нормализация путей;
- `tests/test_commands.py` — команды `ls`, `cd`, `date`, `wc`,
  `uptime`.

Shell-тесты этапов 2–4:

```bash
./tests/test_default.sh
./tests/test_parameters.sh
./tests/test_invalid_script.sh
./tests/test_skip_errors.sh
./tests/test_vfs_minimal.sh
./tests/test_vfs_multiple.sh
./tests/test_vfs_nested.sh
./tests/test_vfs_errors.sh
./tests/test_stage4.sh
```

При успешном прохождении каждый тест выводит:

```text
TEST PASSED
```

или:

```text
ALL ERROR TESTS PASSED
```

или:

```text
STAGE 4 TESTS PASSED
```
