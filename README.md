# Эмулятор командной оболочки

Практическая работа по дисциплине «Конфигурационное управление».

**Вариант №19.**

## Общее описание

Проект представляет собой эмулятор UNIX-подобной командной оболочки
с графическим интерфейсом (Tkinter). Поддерживает параметры командной
строки, выполнение стартовых скриптов, виртуальную файловую систему
(VFS) из ZIP-архива, основные и дополнительные команды.

Выполненные этапы:

- Этап 1. REPL.
- Этап 2. Конфигурация.
- Этап 3. Виртуальная файловая система (VFS).
- Этап 4. Основные команды.
- Этап 5. Дополнительные команды.

## Этап 1. REPL

На первом этапе реализован минимальный прототип эмулятора
с графическим интерфейсом.

Добавлены:

- GUI-окно на Tkinter;
- заголовок окна формируется из реальных данных ОС:
  `Эмулятор - [username@hostname]`;
- разбор команды и аргументов по пробелам;
- команды-заглушки `ls` и `cd`;
- команда `exit`;
- обработка неизвестных команд;
- обработка ошибок при выполнении команд.

## Этап 2. Конфигурация

Поддерживаются параметры командной строки:

- `--vfs` — путь к VFS (ZIP-архив);
- `--script` — путь к стартовому скрипту.

При запуске выводится отладочная информация о переданных параметрах.

Стартовый скрипт выполняется последовательно:

- команда отображается перед выполнением;
- отображается результат выполнения;
- пустые строки и строки с `#` пропускаются;
- при ошибке команды скрипт продолжает работу со следующей строки;
- команда `exit` завершает работу.

Если указан `--script`, эмулятор работает в headless-режиме
(без GUI).

## Этап 3. Виртуальная файловая система (VFS)

Источник VFS — **ZIP-архив**. Содержимое загружается в память,
исходный архив не распаковывается и не модифицируется.

Служебная команда `vfs-info` выводит имя VFS и SHA-256
содержимого архива.

Обрабатываются ошибки: файл не найден, неверный формат.

Тестовые VFS:

- `tests/vfs/minimal.zip` — минимальная;
- `tests/vfs/multiple.zip` — несколько файлов и вложенный каталог;
- `tests/vfs/nested.zip` — три уровня вложенности.

## Этап 4. Основные команды

- `ls [-l] [-h] [-a] [path]` — содержимое каталога VFS.
  Поддерживаются ключи `-l`, `-h`, `-a` и их комбинации.
- `cd <path>` — смена текущего каталога.
- `date` — текущие дата и время.
- `wc <file>` — строки, слова, байты.
- `uptime` — время работы эмулятора.

### Обработка путей

Модуль `src/path_utils.py` нормализует пути:

- абсолютные и относительные;
- `.` и `..`;
- повторяющиеся разделители;
- прямые и обратные слеши.

Пример:

```
/projects/student/files/../../archive/././docs
```

→

```
/projects/archive/docs
```

Выход выше корня VFS невозможен.

## Этап 5. Дополнительные команды

Реализованы команды, изменяющие состояние VFS. Все изменения
выполняются **только в оперативной памяти**. Исходный ZIP-архив
и его содержимое не модифицируются.

### Команда rm

Удаляет файл из VFS.

```text
rm <path>
```

Пример:

```text
$ rm readme.txt
$ ls
config.ini
docs
```

Ошибки:

- отсутствует аргумент;
- путь не найден;
- указан каталог (команда `rm` не удаляет каталоги).

### Команда chown

Изменяет владельца файла или каталога внутри VFS.

```text
chown <owner> <path>
```

Пример:

```text
$ ls -l
- root     35 readme.txt
d root      0 docs

$ chown sergey readme.txt
$ chown admin docs

$ ls -l
- sergey   35 readme.txt
d admin     0 docs
```

Ошибки:

- не указан владелец или путь;
- указано больше двух аргументов;
- путь не найден.

Команда `chown` использует общий механизм нормализации путей,
поэтому поддерживает абсолютные, относительные и сложные пути:

```text
chown user /docs/.././readme.txt
cd docs
chown teacher info.txt
```

### Изменения только в памяти

После перезапуска эмулятора VFS перезагружается из ZIP-архива,
поэтому все изменения `rm` и `chown` исчезают.

Пример:

```text
$ chown sergey readme.txt
$ exit
```

После повторного `./run.sh --vfs tests/vfs/multiple.zip`:

```text
$ ls -l
- root     35 readme.txt
```

### Стартовые скрипты этапа 5

- `tests/stage5_success.txt` — успешные сценарии `chown` и `rm`;
- `tests/stage5_errors.txt` — обработка ошибок.

Запуск:

```bash
./tests/test_stage5.sh
```

Ожидаемый результат:

```text
STAGE 5 TESTS PASSED
```

## Структура проекта

- `src/` — исходный код эмулятора;
- `src/main.py` — GUI + headless, параметры командной строки;
- `src/parser.py` — разбор пользовательского ввода;
- `src/commands.py` — команды и класс `CommandResult`;
- `src/path_utils.py` — обработка и нормализация путей;
- `src/vfs.py` — загрузка VFS из ZIP, вычисление SHA-256;
- `tests/build_vfs.py` — сборка ZIP-архивов VFS;
- `tests/vfs/` — исходные директории тестовых VFS;
- `tests/*.txt` — стартовые сценарии;
- `tests/*.sh` — shell-скрипты тестирования;
- `tests/test_vfs.py` — тесты VFS;
- `tests/test_paths.py` — тесты путей;
- `tests/test_commands.py` — тесты `ls`, `cd`, `date`, `wc`, `uptime`;
- `tests/test_chown.py` — тесты `rm`, `chown`;
- `run.sh` — запуск;
- `README.md`, `.gitignore`.

./run.sh --vfs tests/vfs/multiple.zip --script tests/stage5_success.txt
